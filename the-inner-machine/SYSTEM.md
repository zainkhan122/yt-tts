## Non-negotiable channel identity

The Inner Machine is an original, science-first animated explainer channel about the mechanisms behind ordinary mental experiences. It is **not** The Deeper Mind, not Jungian personality typing, not generic self-help, and not clinical advice.

Every episode must answer:

> What mechanism is running underneath this experience, what evidence supports that explanation, and what should the viewer understand differently afterward?

## Source-of-truth hierarchy

1. Repo `the-inner-machine/` — authoritative files and state.
2. Current workspace — working copy of only what is needed for the active job.
3. Chat memory — never authoritative.

At the start of a session, sync the repo to the workspace before building. Run `python3 tools/cleanup_workbench.py` before every heavy job. Hard safety threshold is 100 MB in the workspace (below the 128 MB snapshot budget); if a render would exceed it, stop and archive/push selected assets or delete intermediates before continuing. After every milestone, update `handoff/HANDOFF.md` and push text/config/state changes to the repo. Never commit secrets, model binaries, stock media or generated video through the text/config push tool.

## Gated workflow

No later gate may run after an earlier gate fails.

1. **Brief gate:** topic passes mechanism test and is not a duplicate.
2. **Research gate:** each factual claim has a source and confidence label; health-sensitive claims receive extra review.
3. **Script gate:** hook in first two sentences, clear promise, 3–4 chapters, midpoint re-hook, honest uncertainty, comment-driving ending, and a measured opening pause after the first vivid line/question.
4. **Asset gate:** every asset has provenance; landscape and portrait pools are separate; no unlicensed or unknown stock.
5. **Storyboard gate:** schema validates, all files exist, every sentence beat has a distinct asset, motion and caption fields complete.
6. **TTS gate:** model/voice/version recorded; measured audio duration creates the timing schedule; no estimated caption timing.
7. **Render gate:** long-form is 16:9, 1920×1080 or 1280×720, 30 fps; every beat is checked; Shorts are 9:16, 1080×1920, 30 fps.
8. **Packaging gate:** three title/thumbnail concepts, title–thumbnail curiosity gap, sources/disclaimer, chapters, pinned comment, disclosure field recorded.
9. **Final gate:** decode spot checks, ffprobe report, loudness report, caption report, asset report and rights report all pass.
10. **Publish gate:** upload checklist complete; disclose AI/synthetic content when required; add end screen and playlist; schedule analytics review.

## Canonical rules

- Long-form: 6–9 minutes initially, 16:9, one clear mechanism.
- Pilot cadence: one long-form every 10–14 days and two Shorts per long-form.
- Voice is a primary product feature: target natural pace (usually 135–150 words/minute), sentence-level speed overrides, intentional pauses, breath room and emphasis. Never accept default fast TTS without listening QA.
- Script is a primary product feature: every sentence must earn its place through a pattern interrupt, concrete image, question, mechanism, contrast or payoff. Remove repeated claims and filler.
- Every sentence receives one timed visual beat. Visuals must be semantically related to the spoken sentence, not generic mood wallpaper. Beat count is not fixed at 52: choose the natural sentence count needed for the finished 6–7 minute script, within the approved 50–65 range.
- Animation must create a live feeling: varied Ken Burns motion, parallax/diagram movement, object reveals, transitions and kinetic emphasis. Never rely on a static slideshow or identical zoom cycle.
- **Kinetic typography is selective emphasis—not captions and not a text layer on every image.** Only approved high-value beats receive 1–3 meaningful overlay words; all other beats are text-free. Use `tools/validate_kinetic.py` as a hard gate. The reference implementation is `pipeline/assemble_v2.py`; `pipeline/render_timed.py` is not a final kinetic-text renderer.
- Visuals support comprehension, not filler. Use diagrams, causal maps, timelines and visual metaphors; cinematic mood alone is insufficient.
- No claim of diagnosis, treatment, “cure,” or universal brain function.
- Use “research suggests,” “one account,” and “evidence is mixed” where appropriate.
- AI is a production aid, not the channel’s authorial identity. The original value must be visible in research, explanation, editorial judgment and visual interpretation.
- Never reuse a previous episode’s hero art or stock clip. Within an episode, every sentence beat must use a distinct visual asset; no reuse is permitted. If a recurring brand element is reused, mark it as `brand_reusable` in the asset manifest and exclude it from sentence-beat assets.
- Thumbnail text: 2–4 words, never the full title, measured to fit, readable at mobile size. Place text in the top-left negative space by default, with a dark scrim/gradient if needed; never cover the main subject, face, focal object or mechanism. If the top-left is not safe, move the text to the nearest clear negative-space region while preserving the same non-obstruction rule.
- All outputs are atomic: write to `.part`, verify, then rename. Failed output is never marked complete.

## Required state transitions

`draft → researched → scripted → assets_ready → storyboard_verified → tts_verified → rendered → packaged → qa_pass → published`

A state transition requires a timestamp, tool version, input checksums and the relevant report path. Manual edits must reset the affected downstream states.
