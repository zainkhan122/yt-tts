6. Target pipeline (proposed)

  1. One preflight, before any cloud dispatch. Brief lint, copy rules (including C040), media mode, capture hashes, and thresholds run locally in one command. Anything that would fail in the cloud fails here, in seconds.
  2. Declared media mode per brief (video, capture, graphic) replaces the hard-coded bypass set. The gate checks the mode, not the ID.
  3. Normalised alignment. Numerals, units, and abbreviations are normalised on both sides before the match score. The threshold stays at the approved level.
  4. Split pins. Media and copy are pinned separately. A copy edit needs a re-check, not a re-render or re-enqueue.
  5. Publish-existing path. A QA-passed artifact can be promoted to the release with a digest check, without re-rendering. Re-renders stay blocked for identical inputs.
  6. Accepted-risk record. Gates such as claim_verifiable can be overridden only with a named owner decision, reason, and date, written to the receipt.
  7. Single source of thresholds, read by pipeline, gate, and channel config.
  8. Clean runs. Gate receipts go to one tracked folder; the remote is restored by a setup script.
Expected effect: the same quality bar, with fewer failed cloud runs. Most of this week's failures would have been caught locally, in seconds, instead of in 15-minute cloud runs.
