# PhoneBox AI-planning acceptance experiment — NOT PASSED

## Provenance and policy

The active Arena.ai agent generated the semantic plan interactively after inspecting the actual narration's 64 word timestamps and the asset catalog. It saved its plan as `arena-agent-semantic-response.json` via `agent_plan.py`. This is real interactive AI-authored planning, but **not** an autonomous model request from the Python service: `run_experiment.py` hands the saved response to the planner contract. Provider/model identifier is not exposed by the Arena session. There was no OpenRouter inference. GitHub Actions Secrets metadata confirmed `OPENROUTER_API_KEY` exists, correcting the earlier local-only audit. The existing OpenRouter pilot remains owner-paused and was not activated or bypassed.

## Narration and alignment

Exact script: `narration.json`. House voice: Chatterbox option-3 generated by review-only workflow run 45791169723. Original `voice.wav` is 22.36 s. A pitch-preserving 0.97x atempo copy `voice-pace-0.97.wav` is 23.0349 s and is the exact rendered narration. Audio was freshly transcribed and aligned with faster-whisper `base.en`; `alignment-pace-0.97.json` reports every word matched and passed the configured 0.5 confidence threshold, no interpolated words or extra tokens. Strict in-memory alignment was independently re-run before planning compilation. Word times and probabilities remain estimates, not a guarantee of perceptual accuracy. Base model on the original audio failed one low-confidence word; other tested models had missing/low-confidence tokens. The 0.97x copy passed without lowering the gate.

## Asset decisions

`catalog.json` lists file paths, descriptions and SHA-256 hashes. `home.png`, `music.png`, and `stats.png` are crops of existing PhoneBox dashboard captures; `editor.png` and `widget.png` are crops of its existing editor capture. These were visually inspected: the screenshots show the depicted controls/metrics; widget crop is a clock tile. `cursor.png` and `disclosure.png` are procedural overlays, not software recordings. The video explicitly labels the animated recreation, though the label is small. Images are not generated by a repository image API.

## Generated plan

- `intro`: move the captured dashboard into view for the control-panel claim.
- `media`: scale up the media-player crop.
- `stats`: move the real metrics capture into view.
- `editor`: move a cropped widget and pointer across a static editor screenshot as an illustrative drag.
- `connection`: move a cursor toward the dashboard USB status; Wi-Fi is narrated but not visually demonstrated.
- `setup`: place dashboard and editor screenshots in a stack; this does not prove that the app and agent are running.

`scheduled.json`, `design.json` and `timeline.json` preserve the phrase-based event schedule and executable layer transforms. `planner-input.json` records words and safe catalog descriptions supplied to the planner contract. The plan was generated interactively, not through an independently callable configured planner. Programmatic renderer validation passed, but that validates structure, not visual truth.

## Output and review

`acceptance-experiment.mp4`: 1080x1920 H.264, 24 fps, 23.04 s, AAC mono. Full FFmpeg video/audio decoding succeeded. A 15-frame contact sheet `qa-contact.jpg` covers the opening, transitions, all eight event times and end; it was visually inspected by the same agent that planned the video, not an independent reviewer. The full audio was not listened to in this environment, so narration synchronization is not fully reviewed.

**Acceptance failures:**
- The plan was produced interactively and then replayed; autonomous planner execution has not been demonstrated.
- Most animations move or scale static screenshots, rather than depict the actual operations/results. Only the widget/cursor movement is a simulated interaction; three meaningful subject-level actions are not demonstrated.
- The cursor's target during the USB section is imprecise. Wireless connection, the two running components and permission differences are not actually demonstrated.
- Screenshots occupy too little of the portrait frame, important details are hard to read, the disclosure label is small and overlaps the lower screenshot in the last scene. There are cuts, not rich transitions; the result does not meet the user's earlier quality standard.
- A complete audiovisual review by an independent reviewer has not occurred. Do not publish or schedule this experiment.
